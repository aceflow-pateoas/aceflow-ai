# Standard 模式使用指南

## 🎯 模式特点

**Standard模式**是AceFlow v3.0推荐的标准流程模式，适用于：
- 大多数软件项目
- 3-10人敏捷团队
- 企业应用开发
- 新功能开发

## 📋 7个标准阶段

### 1. 用户故事分析 (1-2天)
编写用户故事和验收标准，输出：
- 用户故事集
- 验收标准
- 优先级划分
- 故事点估算

### 2. 任务分解 (1天)
将用户故事分解为开发任务，输出：
- 详细任务清单 (每个任务≤8小时)
- 任务依赖关系
- 工期估算
- 风险识别

### 3. 测试用例设计 (1-2天)
设计测试用例和测试策略，输出：
- 测试策略
- 功能测试用例
- 接口测试用例
- 测试数据准备

### 4. 功能实现 (主要开发周期)
开发功能代码，输出：
- 功能实现报告
- 代码变更记录
- 技术决策文档

### 5. 单元测试 (1-2天)
执行单元测试，输出：
- 单元测试报告
- 代码覆盖率分析 (≥80%)
- 失败用例修复

### 6. 集成测试 (1-2天)
执行集成测试，输出：
- 集成测试报告 (通过率≥95%)
- 接口测试结果
- 缺陷列表
- 回归测试结果

### 7. 代码审查 (1天)
审查代码质量，输出：
- 代码审查报告
- 代码质量评分 (≥8/10)
- 问题修复记录

## ⚡ 质量标准

### 代码质量
- 代码覆盖率≥80%
- 代码质量评分≥8/10
- 编码规范遵循

### 测试质量
- 单元测试通过率100%
- 集成测试通过率≥95%

### 交付质量
- 按时交付率≥95%
- 严重问题修复率100%

## 🚀 适用场景

✅ **推荐使用**：
- 企业应用开发
- Web/移动应用
- API服务开发
- 新功能迭代
- 中小型项目

❌ **不推荐使用**：
- 超大型企业项目（使用Complete模式）
- 快速原型验证（可使用更轻量模式）

## 💡 使用提示

1. **团队准备**：确保团队理解Standard模式流程
2. **工具配置**：建议配置基础CI/CD流水线
3. **时间规划**：合理安排各阶段时间，不要压缩测试时间
4. **质量优先**：严格执行质量门控检查
