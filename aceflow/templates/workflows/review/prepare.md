# 审查准备阶段 (Review Preparation)

## 检查清单 (Checklist)

### 必须完成 (Required)

- [ ] **代码变更已梳理**
  明确本次审查的代码范围（PR、分支或commit范围）

- [ ] **自查已完成**
  提交前自己先审查一遍代码

- [ ] **测试已通过**
  所有单元测试和集成测试通过

- [ ] **PR描述已编写**
  清晰说明变更目的、内容和影响范围

- [ ] **审查者已指定**
  确定代码审查人员（或团队）

### 可选项 (Optional)

- [ ] **代码规范检查已运行**
  使用linter、formatter工具检查

- [ ] **复杂逻辑已注释**
  为复杂的代码添加解释说明

- [ ] **相关文档已准备**
  设计文档、接口文档等

## 输出物 (Deliverables)

1. **PR链接**（Pull Request URL）
2. **变更说明**（详细的PR描述）
3. **测试报告**（测试通过截图/日志）
4. **审查清单**（需要重点关注的部分）
5. **相关文档**（设计文档、架构图等）

## PR描述模板 (PR Description Template)

```markdown
## 变更类型
- [ ] 新功能 (Feature)
- [ ] Bug修复 (Bugfix)
- [ ] 重构 (Refactor)
- [ ] 文档 (Documentation)
- [ ] 性能优化 (Performance)

## 变更说明
简要描述本次变更的目的和内容。

## 主要改动
- 修改了文件A，实现了XXX功能
- 重构了模块B，提升了可维护性
- 添加了测试C，覆盖了边界情况

## 测试
- [ ] 单元测试已添加/更新
- [ ] 集成测试已通过
- [ ] 手动测试已完成

## 影响范围
说明本次变更可能影响的模块和功能。

## 截图/演示
（如果适用）添加功能演示截图或GIF。

## 审查要点
建议审查者重点关注的地方。
```
