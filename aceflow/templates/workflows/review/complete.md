# 审查完成阶段 (Review Completion)

## 检查清单 (Checklist)

### 必须完成 (Required)

- [ ] **审查者已批准**
  PR已获得Required Approvals

- [ ] **CI/CD检查已通过**
  所有自动化检查通过

- [ ] **代码已合并**
  PR已合并到目标分支

- [ ] **相关Issue已关联**
  链接并关闭相关Issue

- [ ] **审查总结已编写**
  记录审查过程和经验教训

### 可选项 (Optional)

- [ ] **团队知识分享**
  如有价值的讨论，分享给团队

- [ ] **审查指标已记录**
  记录审查耗时、评论数等指标

## 输出物 (Deliverables)

1. **合并记录**（Merge commit）
2. **审查总结**（Review summary）
3. **经验教训**（Lessons learned）
4. **知识分享**（如适用）

## 合并前检查 (Pre-Merge Checklist)

### 必要条件
- ✅ 获得足够的approvals（通常≥1）
- ✅ 所有discussions已resolved
- ✅ CI/CD pipeline全部通过
- ✅ 没有merge conflicts
- ✅ 目标分支是正确的

### 合并策略选择

**Merge Commit** (推荐)
```
保留完整的提交历史，适合feature分支
```

**Squash and Merge**
```
合并为单个commit，适合小改动或临时分支
```

**Rebase and Merge**
```
保持线性历史，适合个人分支
```

## 审查指标收集 (Review Metrics)

### 有价值的指标

| 指标 | 说明 | 价值 |
|-----|------|-----|
| 审查周期 | 从PR创建到合并的时间 | 衡量响应速度 |
| 审查轮次 | 需要几轮反馈 | 衡量代码质量 |
| 评论数量 | 审查评论总数 | 衡量审查深度 |
| 问题类型 | Bug/安全/性能/质量 | 识别常见问题 |
| 修改规模 | 代码行数变化 | 评估复杂度 |

### 趋势分析

定期分析审查数据，发现问题：
- 审查周期过长？可能需要更多审查者
- 安全问题频繁？需要加强安全培训
- 评论数过多？可能代码质量不够
