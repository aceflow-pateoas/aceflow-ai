# 定位根因阶段 (Root Cause Analysis)

## 检查清单 (Checklist)

### 必须完成 (Required)

- [ ] **问题代码已定位**
  找到导致问题的具体代码位置（文件名、行号）

- [ ] **根本原因已识别**
  理解为什么会出现这个问题（逻辑错误、边界条件、竞态条件等）

- [ ] **修复方案已设计**
  确定如何修复（修改逻辑、添加校验、优化算法等）

- [ ] **潜在副作用已评估**
  修复是否会影响其他功能

### 可选项 (Optional)

- [ ] **调试日志已添加**
  如果需要，添加额外的调试日志辅助定位

- [ ] **单元测试已审查**
  检查现有测试为何没有覆盖此场景

## 输出物 (Deliverables)

1. **问题代码位置**（具体文件和函数）
2. **根因分析报告**（为什么会出现问题）
3. **修复方案设计**（如何修复）
4. **影响分析**（修复可能的副作用）

## 调试技巧 (Debugging Tips)

1. **使用调试工具**: 断点、变量监视、调用堆栈
2. **添加日志输出**: 在关键路径添加日志
3. **二分法排查**: 逐步缩小问题范围
4. **代码审查**: 检查最近的代码变更
5. **数据分析**: 检查异常数据或边界情况

## 完成标准 (Completion Criteria)

- 找到了问题的根本原因
- 设计了合理的修复方案
- 评估了修复的影响范围
