# 评估分析阶段 (Assessment & Analysis)

## 检查清单 (Checklist)

### 必须完成 (Required)

- [ ] **重构目标已明确**
  清楚为什么要重构（提高可维护性、性能优化、消除技术债等）

- [ ] **目标代码已识别**
  明确需要重构的模块、类、函数范围

- [ ] **代码质量问题已列举**
  列出具体问题（复杂度高、重复代码、命名不清晰等）

- [ ] **收益已评估**
  量化重构的价值（代码行数减少、复杂度降低、性能提升等）

- [ ] **风险已识别**
  评估潜在风险（影响范围、测试覆盖不足、依赖关系复杂等）

### 可选项 (Optional)

- [ ] **代码指标已收集**
  圈复杂度、代码重复率、测试覆盖率等

- [ ] **相关文档已审查**
  查看原有设计文档和注释

## 输出物 (Deliverables)

1. **重构目标文档**（为什么重构）
2. **目标代码清单**（哪些文件/函数需要重构）
3. **问题列表**（具体的代码质量问题）
4. **收益评估报告**（重构的价值）
5. **风险评估**（潜在风险和应对措施）

## 评估维度 (Assessment Dimensions)

### 1. 代码复杂度
- 圈复杂度（Cyclomatic Complexity）
- 函数长度
- 嵌套层级

### 2. 代码重复
- 重复代码块
- 相似逻辑

### 3. 可维护性
- 命名规范
- 注释完整性
- 模块耦合度

### 4. 性能
- 时间复杂度
- 空间复杂度
- 潜在瓶颈

## 重构类型参考

- **提取方法** (Extract Method): 将长函数拆分
- **重命名** (Rename): 改善命名
- **消除重复** (Remove Duplication): 提取公共代码
- **简化条件** (Simplify Conditional): 简化复杂的if-else
- **引入设计模式** (Introduce Pattern): 应用设计模式

## 完成标准 (Completion Criteria)

- 清楚重构的目标和范围
- 评估了收益和风险
- 为重构方案设计做好准备
