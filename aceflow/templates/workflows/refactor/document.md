# 文档更新阶段 (Documentation Update)

## 检查清单 (Checklist)

### 必须完成 (Required)

- [ ] **代码注释已更新**
  更新受影响的函数和类的注释

- [ ] **API文档已更新**
  如果有API变化，更新文档

- [ ] **CHANGELOG已记录**
  在CHANGELOG.md中记录重构内容

- [ ] **技术决策已记录**
  记录重构的原因和方案（ADR - Architecture Decision Record）

- [ ] **README已审查**
  确保README与代码一致

### 可选项 (Optional)

- [ ] **设计文档已更新**
  如果有架构变化，更新设计文档

- [ ] **示例代码已更新**
  更新相关的代码示例

- [ ] **知识分享**
  编写博客或内部分享文档

## 输出物 (Deliverables)

1. **更新的代码注释**
2. **更新的API文档**
3. **CHANGELOG条目**
4. **技术决策记录（ADR）**
5. **重构总结报告**

## CHANGELOG 格式示例

```markdown
## [1.3.0] - 2025-01-17

### Refactored
- 重构了用户认证模块，提升代码可维护性
  - 提取了TokenManager类，降低AuthService的复杂度
  - 重命名了多个变量和方法，提高可读性
  - 消除了15%的重复代码
  - 圈复杂度从平均18降低到8
  - 性能提升12%
  - 相关PR: #456
```

## 技术决策记录模板 (ADR Template)

```markdown
# ADR-XXX: [重构标题]

## 状态
已接受 / 进行中 / 已废弃

## 背景
为什么需要这次重构？存在什么问题？

## 决策
我们决定如何重构？

## 理由
为什么选择这种方案？
- 优点1
- 优点2
- 考虑的替代方案

## 后果
### 正面影响
- 代码可维护性提升
- 性能改善

### 负面影响（如果有）
- 需要学习新的结构
- 暂时的开发效率下降

## 实施
- 重构步骤
- 测试策略
- 上线计划
```

## 重构总结报告 (Refactoring Summary)

### 1. 重构目标
说明为什么要进行此次重构

### 2. 重构内容
- 涉及的文件和模块
- 使用的重构技术
- 代码变更统计

### 3. 收益总结
- 代码质量改善（圈复杂度、重复率）
- 性能提升（如果有）
- 可维护性提升

### 4. 经验教训
- 做得好的地方
- 需要改进的地方
- 对未来重构的建议

## 文档类型 (Documentation Types)

### 代码级文档
- 函数/方法注释（docstrings）
- 内联注释（复杂逻辑说明）
- 类型注解（type hints）

### API文档
- 接口说明
- 参数描述
- 返回值说明
- 示例代码

### 架构文档
- 系统架构图
- 模块关系图
- 设计模式说明

### 决策文档
- 技术决策记录（ADR）
- 变更日志（CHANGELOG）
