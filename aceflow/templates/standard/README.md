# Standard 模式使用指南

## 🎯 模式特点

**Standard模式**是AceFlow v3.0中平衡性最好的流程模式,适用于:
- 常规企业应用开发
- 3-10人的中型团队
- 需要标准化流程的项目
- 质量和效率平衡的场景

## 📋 5个标准阶段

### P1: 需求分析 (4-8小时)
详细需求分析和用户故事编写,输出:
- 需求规格说明书
- 用户故事集合
- 功能需求清单
- 验收标准定义

### P2: 技术设计 (4-8小时)
系统架构和技术方案设计,输出:
- 系统架构设计
- API接口定义
- 数据库设计
- 技术选型说明

### D1: 功能开发 (1-3天)
核心功能实现和单元测试,输出:
- 功能代码实现
- 单元测试代码
- 开发文档
- 代码提交记录

### D2: 测试验证 (4-8小时)
全面测试和质量验证,输出:
- 集成测试报告
- 功能测试报告
- 性能测试结果
- Bug修复记录

### R1: 发布准备 (2-4小时)
代码审查和发布准备,输出:
- 代码审查报告
- 部署文档
- 发布检查清单
- 迭代总结报告

## ⚡ 质量标准

### 代码质量
- 代码覆盖率≥75%
- 关键漏洞零容忍
- 编码规范遵循

### 测试质量
- 功能测试通过率≥90%
- 性能指标达标率≥85%
- Bug修复率100%

### 交付质量
- 按时交付率≥85%
- 需求完成率≥90%
- 客户满意度≥7/10

## 🚀 适用场景

✅ **推荐使用**:
- Web应用、移动应用开发
- 企业内部管理系统
- 常规功能迭代
- 中等复杂度项目

❌ **不推荐使用**:
- 快速原型验证(用Minimal)
- 大型复杂系统(用Complete)
- 紧急Bug修复(用Minimal)
- 探索性项目(用Smart)

## 💡 使用提示

1. **团队协作**: Standard模式适合明确分工的团队协作
2. **文档平衡**: 保持必要文档,避免过度文档化
3. **灵活调整**: 可根据实际情况适当简化或增强某些阶段
4. **持续改进**: 定期回顾流程效率,优化瓶颈环节
